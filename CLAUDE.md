# Resonate

A vocal pitch + waveform web app served over LAN so it can be used from a phone. Sing into the mic, see the note name, cents-off, volume, and live waveform.

## Deploy (primary workflow)

Push to `main` → `.github/workflows/deploy.yml` publishes `public/` to the `gh-pages` branch → live on GitHub Pages (HTTPS, so the mic works on a phone with no cert hassle). This is the normal iteration loop: make the change, bump the version badge, push to `main`, tell the user when the deploy finishes. The local server below is only for offline testing.

## UI principles (standing — the user's direction, see docs/ROADMAP.md)

- **Feedback coaches; it doesn't grade.** This is for learning to sing, not a game. Keep every number (scores, cents, timing) in the data (history, sync, the AI coach), but don't put grade-like numbers in front of the singer: no percentages after a line or a take, no scoreboard counts, no red "fail" marks. Lead with what went well, then at most a few concrete things to try, each with a way to hear it. Build this into the data model (observations with a tone), not as a skin over scores.
- **Few words.** Don't explain what the user just did or what a control obviously does. Show the facts that matter compactly (e.g. a song's range before → after a key change, not a paragraph about fitting a profile). Prefer a short label, a symbol or a number with a unit over a sentence.
- **Everything works signed out.** GitHub Pages is the host; signing in (planned) only adds cloud sync and the AI/MCP connection.

## Run (local, optional)

```
cd C:\Data\Claude\resonate
npm start
```

Server prints both HTTP (port 3000) and HTTPS (port 3443) URLs for localhost and every detected LAN IPv4. **In practice the port that matters is 3443 (HTTPS)** — that's the one used from a phone, because `getUserMedia` is blocked on insecure origins for any non-localhost host. Port 3000 (HTTP) is only useful for localhost testing. There's no auto-reload; restart the node process to pick up `server.js` changes. Frontend changes (`public/`) just need a browser refresh.

**Which Network URL to give a phone:** the banner lists *every* IPv4, including virtual adapters — Hyper-V's "vEthernet (Default Switch)" (`172.x`) and VirtualBox host-only (`192.168.56.x`). A phone can't reach those. Pick the **Wi-Fi adapter's** IP (the one on the same subnet as the phone).

**Restarting:** `server.js` calls `listen()` with no `error` handler, so if an instance is already running, `npm start` prints the banner and *then* crashes hard with `EADDRINUSE` on 3000. A running instance holds both 3000 and 3443 — so this error also means "it's already up." To restart cleanly, kill the existing `node` process first (`Get-Process node | Stop-Process`).

## Version marker

Every page shows a `v<N>` badge (`#version`, purple: top right — the shell's in its top bar). The shell.html and tuner.html stubs have none (`grep -L 'v=<N>' public/*.html` lists only them). It exists so you can confirm a frontend change actually reached the phone — bump the number, refresh, check the badge. **To bump, run `node bump.mjs <N>`** (repo root): it sets the badge on every page and puts `?v=<N>` on every local script/module address (`<script src>` — away.js included —, `import … from`, `import()`, `new Worker()`, `addModule()`, `importScripts()`), so a new page only ever loads that version's code. GitHub Pages lets browsers reuse each file for 10 minutes (`max-age=600`), one module at a time: v54's sing.js with a cached v53 library.js failed with "does not provide an export named 'saveClean'" and the Sing page showed nothing but Amazing Grace. A new module must be imported with the `?v=` suffix too (the script adds it to any `.js` import). The song library's clean-up cache is keyed by the badge as well. If the badge doesn't change after a refresh, the phone is serving a cached `index.html` — hard-refresh / pull-to-refresh (a Home Screen app: swipe it away and open it again).

## Pitch detection (`public/pitch.js`; the tuner: `public/shell/tuner.js`)

The old Tuner's (`app.js`, gone in cleanup C phase 4) detection, shared by every page that listens. YIN algorithm (de Cheveigné & Kawahara, 2002). Chosen over FFT peak-picking because YIN avoids the octave errors that vocals trigger. Inner loop is bounded to `tau ∈ [minTau, maxTau]` covering only the vocal range (~50–1100 Hz) — keeps it cheap enough for phones.

`createYin`'s detector sets `halfN = buf.length - maxTau` so the autocorrelation uses every sample the largest lag will allow, instead of the standard `buf.length / 2`. This is what makes low-pitch detection viable at fftSize 4096; reverting halfN to `buf.length >> 1` halves the cycles available for sub-100 Hz pitches and the dip stops triggering. The threshold for accepting a YIN dip is 0.2 (paper suggests 0.1–0.15; relaxed because low-fundamental vocals often don't dip below 0.15).

**Our own sound (v97):** after a Piano key (pianoview → `tuner.settle`) or Voice's reference note, a reader that listens again gates at MIN_RMS until the sound has left the mic's window: piano.js `holdPiano(...).stopsAt()` (release + 6τ) → pitch.js `soundGone(ac, end)` (+ output latency + 20 ms + FFT_SIZE samples; ≈ 865 ms after the release). A calibrated gate below MIN_RMS read the tail as the note sung; it isn't filtered by pitch, since the singer sings the note just played. tools/quietvoice.cjs P, H.

Mic constraints disable `echoCancellation`, `noiseSuppression`, and `autoGainControl`. Browser defaults distort pitch and amplitude in ways that break detection and meter scaling.

## Locked-note display logic (`public/shell/tuner.js` `showPitch`)

The shown note isn't `round(current pitch)` — that flickers when vibrato lands near a semitone boundary and lags badly when the user intentionally jumps to a new note. Instead:

- `locked` is a single integer MIDI we currently display.
- Cents number + needle = long-window median (1.5 s) compared to `locked`.
- Each frame, the **short-window median** (300 ms) is compared to `locked`. If it's >50¢ off, an off-note timer starts and the note dims (`data-onnote="false"`).
- If the short median stays >50¢ off for **250 ms**, we re-lock to `round(short median)` and trim history older than the short window so the long median resnaps.

Net feel: holding a note is rock-stable; intentional jumps cause a brief dim then a clean snap.

## Tunable constants (top of `public/shell/tuner.js`; the gates in `public/pitch.js`)

| const | default | effect |
|---|---|---|
| `PITCH_WINDOW_MS` | 1500 | long smoothing — bigger = more stable cents number, slower settle |
| `SWITCH_WINDOW_MS` | 300 | live-pitch window — smaller = more reactive but jitterier |
| `SWITCH_DELAY_MS` | 250 | grace period before snapping to a new note |
| `MIN_RMS` | 0.012 | loudness gate until this device's volume is calibrated (then `vol.gate`, `micGate`) — raise if room noise produces false readings |
| `GATE_DB` | 6 | (pitch.js) a calibrated gate sits this far above the room's noise, or under your quietest hold when that's higher |
| `MIN_CLARITY` | 0.80 | YIN clarity threshold — raise for stricter readings |
| `MIN_FREQ` / `MAX_FREQ` | 50 / 1100 Hz | vocal range bound for YIN; sets `minTau`/`maxTau` |
| `VOL_FLOOR_DEFAULT` / `VOL_CEIL_DEFAULT` | −65 / −5 dB | the level bar's range until the voice profile is calibrated |
| `WATCHDOG_MS` | 8000 | the mic never answered: Start can be tapped again |

## Volume meter (`public/shell/tuner.js` `showLevel`)

The level bar maps dB between the voice profile's calibrated floor and ceiling (Voice's silence + two guided holds: quiet = 25th, loud = 90th percentile; −65 / −5 dB until calibrated), clamped 0–100%. With a calibration the number beside it is 1–10: the median dB over the last 2 s (`VOL_STEADY_MS`) on that scale. The old Tuner used the same scale.

## Record page note segmentation (`public/record.js`)

Per frame: YIN pitch (`pitch.js`, same settings as the tuner) → median over `SMOOTH_MS` (100 ms). A note continues while the smoothed pitch stays within 50¢ of the note's median; it splits when the pitch sits >50¢ away for `SPLIT_MS` (80 ms), and ends on an unvoiced gap ≥ `GAP_MS` (70 ms). Notes shorter than `MIN_NOTE_MS` (60 ms) are dropped. Voicing also requires the RMS of the newest `TAIL_SAMPLES` (1024, ~21 ms) to pass the loudness gate (`MIN_RMS`, or this device's calibrated gate) — the full 4096-sample window smears short gaps, which otherwise merges repeated same-pitch notes. No beat grid yet; times are seconds.

## Sing mode (karaoke, `sing.js`)

The **score is the clock** (an earlier version aligned sung notes to the score ignoring rhythm — dropped: wrong notes leave nothing reliable to align on).

**Parsing (`musicxml.js`):** picks the part+voice with the most lyric syllables (the melody — e.g. soprano of an SATB hymn). Tracks position across all voices (`backup`/`forward`) so each note gets an `onset` and `dur` in quarter notes; measure starts in `measures` (a short first measure = pickup). Syllables printed under the melody's staff but attached to another voice there (recognition gives a syllable to the chord nearest the words — in a piano part often the accompaniment under the tune: The Longest Time's "For the long-est" came out "For ‿ long ‿") move to the melody note starting at the same moment, when it has none of its own for that verse; a hymn's identical words under every voice are untouched. Keeps the highest note of chords, skips grace/cue notes, merges ties — and also merges the first note of a new system/page (`<print new-system|new-page>`) into the previous sung note when it has the same pitch, no syllable in any verse and no rest between: a tie split by a line break, which OMR (Audiveris) often loses across pages; rests become gaps (and `restBefore`). Tempo = first `<sound tempo>` or `<metronome>` (its per-minute's first number: "about 76"; default 90 if none), time signature from the first `<time>`, and every measure's meter in `score.meters` (kept through unfolding; v52) — the Sing page counts in, clicks and taps in the meter where the singing starts (`meterAt`; `countInMeter`: the entry bar's own meter, or the next bar's when the entry bar is a pickup — one meter for the count-in's beats, pace and accents, v53), so Piano Man's 4/4 "Freely" intro doesn't give its 3/4 song a 5-click 4/4 count-in. Lyrics per verse; a note with no syllable after a sung one is a melisma continuation (`‿`). **Repeats are followed** (`readStructure` → `performanceOrder` → `unfold`): barlines (repeats with `times`) and directions (segno/coda signs, `<sound>` segno/dalsegno/dacapo/tocoda/coda/fine, words "D.S."/"D.C."/"To Coda"/"Fine") are read from every part, `<ending>` brackets from the top part only (they're drawn above the system; Audiveris reads piano 8va lines as endings on lower staves — Wichita's piano had three); ending numbers "1, 2" / "1.2.3." are lists, "1-3" and Audiveris's "1,,3" (its export of a printed "1.-3.") ranges. A repeat goes back to the last forward repeat (or the start, or just after the previous repeat) and plays `times` times, or one more than its ending's highest number, and — when no D.S./D.C. comes back — at least as many times as its section has verses (max 8); an ending plays on its numbered passes, one past all its numbers that doesn't repeat is the final ending; a 1st ending that stops just before its repeat sign runs to it (Wichita: Audiveris put "1." on m21 only, the repeat is at m22); after a D.S./D.C. repeats aren't retaken, first endings are skipped, To Coda jumps to the Coda, Fine ends; D.S. with no segno found is ignored. Each played measure gets a verse *pass*: the pass of the repeat it's in, 1 for new music after a repeat or a final ending, after a D.S./D.C. one more than the times its target was sung. A note sings verse k if it has it; after the last verse-k word of its measure, the latest verse it has when the following music has no verse k (a refrain printed once under line 1); in the last measure before a repeat sign, the next verse's word (a pickup printed on line 2 in a 1st ending); a measure with no verse k at all sings the latest verse it has. The chosen syllable becomes verse "1" (`score.verses` = ["1"], so the verse menu disappears) and `score.unfolded` = {written, played, passes} — unless the song has stacked verses no pass reaches (a hymn with a repeated refrain): then the written order and the verse menu stay. A note tied across a jump (into a 1st ending, over To Coda) is cut at the jump; a note right after a jump starts a new lyric line only if a rest precedes it (Wichita's "small va-ca-tion" stays on one line). Wichita: "…small va-" → back to the verse for "-cation, but it don't look like rain" (pass 2, refrain words reused) → 2nd ending → Coda (its repeat twice). Killing Me Softly: 69 written → 107 played measures (verse/chorus twice, bridge, chorus repeat); only verse-1 words in the score, so pass 2 repeats them. tools/repeatcases.cjs (20 cases: endings, AABB, intro vamp, no forward sign, D.S./D.C., hymn, refrain pickup, 1st-ending pickup, tie cut), tools/flow.cjs (a song's lyric lines in performance order). Lyric text cleanup: a performance direction read as a syllable ("sim.", "simile", "cresc.", "rit."…) is dropped; verse numbers stripped, `I 'm` (often with a non-breaking space) → `I'm`. `lyricLines()` splits a verse into display lines at rests and line-ending punctuation. Title falls back to the largest-font `<credit-words>`.

**Session:** one AudioContext for mic + guide so clocks match. Count-in = one bar (+ the missing beats of a pickup bar, fractional when the pickup isn't whole beats — an eighth pickup in 4/4 is 7½: the pickup lands on the "and" of 4; rounding used to put the song half a beat late against its own count-in, v58) of clicks, in the *felt* beat (`feltBeat`: a dotted quarter in 6/8, 9/8, 12/8, else the meter's unit); the guide's clicks (`beatGrid`) too, and a pickup bar (written measure 0, `score.measureOf`, and its replays) counts back from its barline; `songT0` = song time 0 on the audio clock. **Entry bar:** the count-in, clicks, lane and Listen start at the bar containing the first sung note (`entryIdx`/`entryT`), so songs with an instrumental intro (e.g. art songs) don't make you wait through it. `songT0` is offset so song time stays absolute.

**Frame timing:** `frameT = songT − ANALYSIS_LAG − latency`, where `latency = outputLatency (or baseLatency) + INPUT_LATENCY (20 ms)` — the singer follows what they hear late, the mic hears them late, and a pitch frame lags its audio.

**Grading (`grade.js`, v44):** each note's slot may move — its start up to `MAX_SHIFT` (0.24 s) either way in 30 ms steps, chosen for the whole take at once by dynamic programming over the notes (they stay in order, a moved slot keeps ≥ 40% of its length; moving costs `MOVE` 0.15/s, changing the shift between joined notes `DRIFT` 0.1/s, across a rest 0.03/s), cost = the *time* in the whole slot not within 50¢ (additive: each frame is charged once whichever slot it's in, so moving a boundary only pays when frames really match the note they move into — v47; the first version weighted by note length × miss share, which let scoops and silences be spread over a longer neighbour: a correct short note after a scoop went "off", a silent repeated note borrowed its same-pitch neighbour's ring-over and went "good"), plus time the note was sung in the rest *before* it (early entries; a note rung on into the rest after it is phrasing and free — charging that pushed the last note +0.24 late and turned the note before it "off"). For a note after a rest, up to 2 semitones flat counts as on the note when *aligning* (scooped entries aren't "late"; silence still is). Frames are looked up 2×`MAX_SHIFT` around each note (rest regions not clipped). A rusher's right notes used to land in the neighbouring slot and be marked off: a simulated singer 150 ms early on Amazing Grace scored 62% (9 off, 3 missed) before, 97% after. A note is then judged on its moved slot minus the grace (`min(120 ms, 25%)`): voiced ≥ 35% → median octave-folded deviation ≤25¢ good, ≤50¢ close (ok), else off; else loud-but-unpitched (rms ≥ `loudGate`: `MIN_RMS` (`LOUD_MIN`, also on a calibrated device — the only floor against a noise that starts mid-take; the reader's lower gate still lets the pitches through) or 2.5× the quietest quarter second of the take's median rms, whichever is higher — v47, so a fan or traffic doesn't make skipped notes "unclear") + voiced ≥ 50% → **unclear** ("couldn't hear the pitch" — not counted in the %; dotted chip, light blue), else missed. Grades carry `shift` (s, − = early), `from`/`to` (the moved slot). `hit` = share of the slot's frames within 50¢; the take's % (`takeScore`) = duration-weighted mean `hit` over notes not unsung/unclear. Summary adds "· N UNCLEAR" and "· EARLY/LATE ~.15 S" (`timingTendency`: median shift of in-tune notes, shown from 80 ms). During the take a note is graded alone (`gradeLive`, its best shift) once frames pass its end + `MAX_SHIFT`; at the end `gradeTake` regrades all and the pitch line is recoloured against each frame's matched note. - **Model:** the song is grouped into **phrases** (`groupPhrases`: lyric lines joined to ≥ 6 syllables and ≥ 2.5 s, closed at rests/punctuation up to 16 syllables or 10 s; hard boundaries at a rest ≥ 1 bar, a repeat jump, a verse-pass change — notes now carry `pass`, `measure`, `mi`, `wmidi`; durations from the song's own tempo — typed/tapped bpm, a tapped map's average, else the score's — never the tempo %, so slowing down never regroups) and **sections** (~75 s). Each phrase earns **♩ in time → ♪ in tune → ✓ in the song**, keyed by `mk` (music: written intervals + durations, so repeats/verses with the same tune share ♩♪ and transposing keeps them) and `wk` (music + words: reached, ✓). Nothing is locked: a phrase already in time and in tune gets both (credit); the singer can pick anything (More).
- **A step** (`nextStep`, pure, first match wins): Hear it (Listen to the first section; skipped when the song has history or a saved take; "I know it") → the **first run** (sing the first section, Perform view; gives credit: ♩ for a timing pass, ♪ at the credit bar) → per phrase a **block of rounds**: listen (the melody, mic closed) → your turn (count-in, click guide forced, `startSing(part)` with `guided`, lane per round) → one result, repeated by itself until **secured** (2 passes in the last 3 counted rounds, the latest a confirm round with less on screen: In time — lane neutral, confirm lane off; In tune — live colours, confirm bars without your pitch line). Struggle steps down quietly: same again → **slower** (90%, 80%; `retime()` — the song's times at that rate for the round only, never stored/synced/announced, put back when the block ends) → rotate to another phrase after 6 counted rounds, park after 2 rotations; 2 unclear rounds → a **self-check** ("✓ Yes · Again · ▶ You"; Yes secures, the phrase is `thin`). **Runs** ("Sing to “X”", Perform view, lane off, recorded, ending by themselves after X) chain phrases back into the song and give ✓; **Sing on** moves to the next section; **Sing it through** at the end; "Good place to stop" now and then. While a block runs the card shows the step, then the result; ■ Stop on the footer.
- **Verdicts** (`timeVerdict`/`tuneVerdict`) per phrase from `take.rhythm.phrases` (PhraseRhythm, built in takerhythm.js `rhythmOf` → `phraseRhythm` for a guided span's phrases, or the song's phrases for a free take while guiding): timing never rests on the pitch grade — a **counting slip** (the first sound after the silent count-in ≥ max(0.6 beat, 0.25 s) late: `firstSound`; also after a quiet rest inside a run) comes first ("Count in — “Its” a beat sooner"), then unheard (`voiceCover` < 30%, the count-in as the quiet floor), phrase observations (late-in, rushing, short/held…), behind/ahead only in rounds with a measured trip ≤ 0.1 s and ≥ 4 on-beat attacks, else unsure (the pitch grading's moved slots can stand in). In a guided span: the first note is an entry after the count-in, a "missed" note that was voiced (`noteCover` ≥ 20%) is still searched for an onset (v75 dropped it — a late entry came out as "Sing out"), loose glides for in-time rounds (legato on wrong pitches), a tighter lead seed when calibrated. Pitch: pass ≥ 0.80 with no missed and no off note ≥ 1 beat; credit ≥ 0.90. All thresholds in `PRACTICE` (practice.js).
- **Words** (`roundResult`, `runResult`, `securedText` in coach.js): `✓ <win> · <cue>` — a true win first (progress: "“Its” on the beat now"; timing: "In on “That”", "Held “grace” full length", "Steady"; tune: "“sweet” right on A♭4"; "Full speed"), at most one cue ("“sweet” — up to B4", "Hold “me” full length", "Count in — …"), never a score, %, red, or a fault on unsure data; the cue's ▶ plays the note / the phrase. ## Take playback (record page)

The take clock is `mic.ac.currentTime - ctxT0` (not `performance.now()`), so pitch frames and captured audio share one timebase. `recorder-worklet.js` posts the audio-clock time of its first sample plus `Float32Array` chunks; on stop they're stitched into `voice` (peak-normalised gain). Modes: **Voice** (recording), **Notes** (a piano note per detected note), **Both**. Piano notes are shifted earlier by `ANALYSIS_LAG` (50 ms) because a pitch frame describes the trailing 85 ms window — measured lag is ~47 ms. Tap the roll or a chip to move the play cursor. iOS: `navigator.audioSession.type` is set to `playback` for playback (speaker, ignores silent switch) and `play-and-record` before the mic opens. `window.resonateDebug()` (record and sing pages) exposes state for automated tests. Record takes auto-stop at `MAX_TAKE_SEC` (300 s).

Piano: `public/piano/` holds Salamander Grand Piano samples (CC-BY 3.0, attribution in `piano/README.md`), one every minor third A1–C7, trimmed to 3 s mono 64 kbps (~530 KB total). Lazy-loaded (the mp3s kept per page, `sampleFile`) and decoded once per sample rate (`piano.js`; v80: a later context at that rate — one that replaced a closed or "interrupted" one — plays the same buffers at once; `pianoNow(ac)` gives the decoded piano synchronously, `primeHold(ac)` makes the held tone's wave ahead of the first key), played a few seconds ahead at a time (`scheduleAhead`, see Sing → Scheduling ahead); each note uses the nearest sample pitch-shifted via `playbackRate`, starts `ONSET` (12 ms) into the file, and is damped with `RELEASE` when the note ends. Pitch of every sample verified against its name (all within normal piano stretch tuning).

## In-browser OMR (PDF → Song)

Audiveris (Java 25 upstream) runs unmodified-in-spirit inside **CheerpJ 4.2** (WebAssembly JVM, loaded from Leaning Technologies' CDN, Community Edition = personal use). Details in `public/omr/README.md` and `omr-build/README.md`; the short version:

- **Build** (`omr-build/build.sh`): upstream commit `7a36078` + `omr-build/patches/` → compiled with `--release 17` (CheerpJ 4.2 runs ≤ Java 17) → every jar through `StripVolatile.java` → `public/omr/lib/`. Patch 0001 = Java 17 port (pattern switches etc.), 0002 = browser runtime (WebOCR, HOME fallback, web-safe thread pool), 0003 = no AWT in batch (EDT checks only with a GUI), 0004 = lyrics fix (an extender line `pain____` read as a huge-font word made Audiveris drop the whole OCR line — half the syllables; not browser-specific). 0005 = batch robustness: a failed sheet is logged as `Sheet#N failed at STEP: reason` and left out while the other sheets are still exported (`Partial transcription: K of N sheets…`, plus a warning when the first sheet — title/tempo/time signature — is the one missing; before, one bad sheet meant no export at all); every glyph of the music font (156 for Bravura) is checked at startup (outline + a few raster checks; ~1.5 s in CheerpJ, logged as `glyphs checked in N ms`), the font is recreated once if bad, else one ERROR `Music font Bravura unusable: … F_CLEF U+E062 …` naming the failing glyphs and no export; an empty glyph mid-run is also fatal (no silent wrong clefs); `audiveris.fonts.dir` reads font files in place. 0006 = octave clefs: F_CLEF_8VA/8VB were excluded from header clefs ("extremely rare") and the classifier grades octave clefs low (~0.1–0.3 vs ~0.8 for the plain clef), so a low voice's bass-clef-8vb came out an octave high; now the octave variant is used when the classifier proposes it for a glyph extending ≥ ½ interline past the plain clef (below for 8vb, above for 8va) — logged `Staff#N F_CLEF_8VB with an 8 below`. No book yet → the engine from sheet 1 with the stored pages; page prep unfinished → over from the stored PDF; MusicXML made → only the save; a job made by another engine starts over from the stored PDF (`ENGINE` in omr.js = the jar's commit + 8 hex of its SHA-256 + the CheerpJ version; tools/jobstore.cjs fails when lib/ changes without it — not tied to the badge). **Crash-loop guard:** a run goes through stages — `prep` (page prep, or a resumed run's re-render), `boot` (the engine starting), each sheet, `export`, `save` — and each start of one is counted (`job.starts[stage]`, `job.stage` the last begun; a stage a run passed is cleared); a pagehide isn't a crash, nor an end while the tab was hidden (`resonate.import.left` = {id, stage}, set on pagehide / hidden and again at every stage begun while hidden — it used to blame the sheet it was hidden in, so one real crash in the next read "stopped twice" —, cleared when visible again — iOS ends background tabs); the stage a run ended in begun twice without finishing (iOS ending the tab, a renderer crash) → no auto-resume, the job bar above the Reader says "Page 3 stopped twice" · **Skip page 3** (drawn 1×1: the engine fails it at SCALE in ~0.1 s and exports the rest — checked natively; reported "left out: it stopped the engine twice") · **Retry** (the Reader's ✕ forgets it), or for another stage "Stopped twice: pages / engine / MusicXML / saving" · Retry (the crash seen at a resumed export, below, used to resume into itself on every visit). The Reader's ✕ also stops and forgets a running import, and one an error kept (not while another tab runs it); it waits for a book being checked or stored (every write of a running job goes through one queue, none after ✕ — the book after a sheet used to write the job back, so the next load showed the forgotten import). pagehide stops the engine (the lock frees for the next page; back from the bfcache → reload); a reload asks first only when the job couldn't be stored (storage full). The screen wake lock is asked in the tap that picks the file and again whenever the tab comes back or on the next tap (v80 never re-asked after the tab was hidden), and let go however the run ends (saved, an error, refused, stopped — an error used to keep the screen on).
